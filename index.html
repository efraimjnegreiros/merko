Resumo

Apresentamos um sistema de gestão de vendas construído inteiramente em C++17, cobrindo o ciclo completo de uma aplicação de negócio: modelagem de domínio orientada a objetos, persistência relacional e interface web — sem depender de frameworks externos. O domínio é organizado em quatro hierarquias abstratas (Pessoas, Produtos, Transações e Pagamentos), cada uma explorando herança e polimorfismo reais via métodos virtuais puros. A persistência usa SQLite3 embutido como amalgamation, com uma camada de DAO que mapeia a herança do domínio para tabelas relacionais e reconstrói os objetos polimórficos a partir do banco. O backend expõe uma API REST via cpp-httplib, e um segundo programa (merko-front) consome essa API para renderizar as telas no servidor, inteiramente em C++, sem JavaScript.

O que o sistema faz

01

Cadastro de pessoas

Clientes, vendedores (com comissão) e fornecedores, todos herdando de uma classe Pessoa comum.

02

Controle de estoque

Produtos perecíveis e não perecíveis, com alerta de validade, garantia e baixo estoque.

03

Compras e vendas

Transações com múltiplos itens, desconto percentual e atualização automática de estoque.

04

Pagamentos

Dinheiro (com troco), cartão (parcelado) e Pix, cada um com sua própria validação.

05

Cálculo de comissão

Comissão do vendedor calculada sobre o total efetivamente vendido no período.

06

API REST completa

CRUD de toda entidade via HTTP/JSON, pronta para qualquer cliente consumir.

Modelo de domínio

O domínio segue quatro hierarquias abstratas: Pessoa → Cliente, Funcionario → Vendedor, Fornecedor; Produto → ProdutoPerecivel, ProdutoNaoPerecivel; Transacao → Compra, Venda; Pagamento → Dinheiro, Cartao, Pix. Cada classe-base declara métodos virtuais puros implementados de forma diferente em cada subclasse concreta. A persistência mapeia essa herança com tabela base + tabela por subtipo e coluna discriminadora.
